# START HERE — проект «Розница»

Этот файл задаёт обязательный порядок старта проекта в любом новом чате/агенте.

## Триггер
Если пользователь пишет что-то вроде:
- «Продолжаем Розницу»;
- «Работаем по Рознице»;
- «Продолжаем закупки/подбор по Рознице»;
- или явно ссылается на репозиторий `KVAKUSK/roznitsa-procurement-control`,

не начинать подбор по памяти и не просить пользователя пересказывать правила.

## Обязательный порядок действий
1. Прочитать `context/HANDOFF_CURRENT.md` в этом репозитории.
2. Найти в Library `/работа/РЕГЛАМЕНТ РОЗНИЦА ЗАЯВКА_актуальный.docx` и прочитать актуальный регламент целиком.
3. Прочитать Airtable: база `Закупки — подбор и контроль`, таблица `Подтвержденные решения`, учитывать активные решения со статусом `Подтверждено Леной`.
4. Найти актуальный рабочий Excel из Library, указанный в handoff, и работать только после шагов 1–3.
5. Текущие цены, поставщика, наличие и вложимость подтверждать по актуальным прайсам. История и Airtable — правила/подсказки, но не замена текущему прайсу.

## Приоритет источников
При противоречиях использовать такой порядок:
1. Явное новое указание Лены в текущем чате.
2. Активное подтвержденное решение Лены в Airtable.
3. Актуальный регламент из Library.
4. `context/HANDOFF_CURRENT.md` как состояние проекта и навигация.
5. Исторические листы/предыдущие заявки как подсказка.
6. Автоматическое предположение ассистента — только как кандидат, не как подтвержденное правило.

## Ключевой принцип накопления знаний
Если Лена при проверке говорит, что вариант подходит, не подходит, относится/не относится к категории, указывает правильного производителя/поставщика/формат/массу или формулирует общее правило — это нужно занести в Airtable `Подтвержденные решения` без отдельной просьбы «запиши в Airtable».

Если замечание по смыслу общее, не ограничивать его конкретным брендом или строкой. Например, запрет использовать один и тот же удобный аналог для большого числа разных запросов относится ко всем категориям, если ассортимент позволяет подобрать несколько разных подходящих вариантов.

## Что нельзя делать
- Нельзя начинать новую работу только по памяти чата.
- Нельзя считать handoff заменой регламента.
- Нельзя считать Airtable заменой актуального прайса.
- Нельзя автоматически превращать собственное предложение ассистента в подтвержденное правило без подтверждения Лены.

Этот файл — постоянная точка входа. `context/HANDOFF_CURRENT.md` содержит текущее состояние проекта и может обновляться по мере работы.
