# Handoff — проект «Розница»

Дата актуализации: 2026-10-26

Этот файл — точка входа для нового чата/агента. Перед любой новой работой по проекту ОБЯЗАТЕЛЬНО:
1. прочитать этот файл;
2. найти и прочитать актуальный регламент `/работа/РЕГЛАМЕНТ РОЗНИЦА ЗАЯВКА_актуальный.docx`;
3. прочитать Airtable → база `Закупки — подбор и контроль` → таблица `Подтвержденные решения`;
4. только после этого менять таблицу или подбирать аналоги.

GitHub хранит точку входа и обязательные правила процесса. Airtable хранит накопительный живой справочник подтвержденных Леной решений и запретов. Регламент хранит стабильные базовые правила подбора. Ни один из этих источников не заменяет остальные.

При работе в новом чате нужно найти эти файлы именно в Library `/работа`, а не брать более старые версии из предыдущих разговоров.

Источники/подсказки внутри/рядом с проектом:
- вкладка `Прод июль-сент 25` в рабочей книге — историческая подсказка по тому, что ставили раньше;
- Airtable `Подтвержденные решения` — обязательный накопительный справочник ручных подтверждений и запретов Лены;
- актуальные прайсы поставщиков — источник текущей цены, наличия и поставщика;
- исторический лист и Airtable НЕ являются источниками текущей цены, если цена не подтверждена актуальным прайсом.

## 2. Кто такая «Лена» в таблице

Пользователь = Лена. Колонка `Лена комментарий` пишется от её лица и должна быть короткой.

Нормальный формат комментария:
`30 шт/кор; ООО «Ресурс»; 25,82 ₽/шт`

Не писать в комментарии:
- слово «вложимость»;
- название источника/прайса и номер строки;
- длинные объяснения;
- `производитель не подтвержден`;
- `подбор снят`.

Если цена уже стоит в отдельной колонке и расчёт на штуку не нужен — комментарий можно оставить как `NN шт/кор; Производитель`.

## 3. Главный принцип подбора

Пустых рабочих строк быть не должно. Для каждой рабочей позиции должно быть либо:
- `ДА`, если найден фактически тот же товар (допустимы сокращения/другой порядок слов), либо
- настоящий, осмысленный аналог.

Нельзя закрывать строку случайным товаром только ради отсутствия пустоты.

Порядок выбора аналога:
1. Сначала ЖЁСТКО товарная категория.
2. Затем формат/тип упаковки.
3. Затем масса/объём.
4. Затем бренд/линейка.
5. Затем вкус/вариант.
6. И только после этого — цена среди сопоставимых вариантов.

Примеры жёстких правил:
- бульон → бульон;
- суп → суп;
- крем-суп/суп-пюре → сначала крем-суп/суп-пюре, затем близкий суп;
- картофельное пюре → картофельное пюре;
- рисовое готовое блюдо → рис/готовое блюдо, не лапша;
- мягкая пачка → в первую очередь мягкая пачка;
- чашка/лоток → в первую очередь тот же формат.

## 4. Масса и ассортимент

Нельзя выбирать 40 г, если в прайсах есть нормальный близкий вариант 70–75 г для запроса 72 г.

ОБЩЕЕ ПРАВИЛО ДЛЯ ВСЕХ КАТЕГОРИЙ: нельзя брать один удобный аналог и подставлять его в большое количество разных строк только потому, что он подходит по общей категории, весу или кажется универсальным.

Если в прайсах есть ассортимент, нужно сохранять разнообразие и подбирать несколько действительно подходящих вариантов с учётом:
- категории;
- бренда и линейки;
- вкуса/варианта;
- формата;
- фасовки/массы;
- производителя.

Один и тот же аналог можно повторять только если он объективно лучший для нескольких строк и в актуальных прайсах нет других более подходящих вариантов.

Это правило относится НЕ только к Doshirak/Ottogi или корейской лапше, а ко всем ассортиментным группам.

По корейской лапше особенно внимательно смотреть прайс Кима и не сокращать ассортимент до одной-двух универсальных позиций. Nongshim, Ottogi, Samyang, DAESANG, Simeite и др. не смешивать без необходимости.

## 5. Airtable — накопительный справочник подтвержденных решений

База: `Закупки — подбор и контроль`.
Таблица: `Подтвержденные решения`.

Перед каждым новым подбором обязательно читать эту таблицу и учитывать активные решения со статусом `Подтверждено Леной`.

Как пополнять справочник:
- если Лена говорит `правильно`, `оставляем`, `подходит`, `вот этот вариант верный` — сохранить это как положительное подтвержденное решение;
- если Лена говорит `это к этому не относится`, `так не подбирать`, `этот производитель неверный`, `этого поставщика не использовать` — сохранить как запрет/исключение;
- если Лена формулирует общее правило на примере одной позиции, не ограничивать правило только этой маркой/строкой, если смысл явно общий;
- собственное предложение ассистента без явного подтверждения Лены НЕ считать подтвержденным правилом.

Airtable — живой накопительный слой. Если новое подтвержденное правило противоречит старому, старое нужно отметить как отмененное/замененное или обновить.

## 6. Историческая вкладка `Прод июль-сент 25`

Использовать как обязательную подсказку:
- проверить, встречалась ли такая же или близкая позиция раньше;
- посмотреть прошлый товар, поставщика, фасовку и смысл соответствия;
- если новый алгоритм предлагает принципиально другой товар — это триггер на ручную перепроверку.

Но текущие цена/поставщик/наличие всегда подтверждаются по актуальному прайсу.

## 7. Поставщики и специальные правила

- `Тэн` — полностью исключён.
- `Че Ман Су` — полностью исключён.
- `Восток` разрешён для позиций из `Прайс Орими`; при этом поставщик = `Восток`, а `Орими` — производитель/группа, НЕ поставщик.
- Richard из Project Invest → поставщик `Проект Инвест`.
- Greenfield / Jardin / Jockey / TESS из `Прайс Орими` → поставщик `Восток`.

Поставщик в итоговой строке = тот, чей актуальный прайс содержит выбранную позицию.

## 8. Производитель

Производитель обязателен. Поставщик и производитель — разные сущности.

Если производителя нет в прайсе, разрешён поиск по открытым источникам. Нельзя оставлять финальный комментарий `производитель не подтвержден`.

Частые подтверждённые соответствия:
- Nongshim → Nongshim Co., Ltd.
- Ottogi → Ottogi Corporation.
- Samyang → Samyang Foods Co., Ltd.
- Doshirak / Квисти → ООО «Доширак Коя».
- Big Lunch / Бизнес Ланч → ООО ТПК «БиоФуд».
- Увелка → ООО «Ресурс».
- Greenfield / TESS / Jardin / Жокей → ООО «Орими».

## 11. Инструментальная логика

Для Excel-правок использовать установленный spreadsheet workflow / artifact_tool, не openpyxl, если рабочая среда доступна и регламент инструмента не предписывает иное.

После основного подбора нужен отдельный аудит:
- переходы между категориями;
- слишком большая разница массы;
- повтор одного аналога в большом числе строк;
- несоответствие поставщика актуальному прайсу;
- пустой/неверный производитель;
- запрещённые поставщики;
- пустые рабочие позиции.

Data Analytics использовать именно как независимый аудит качества, а не как источник цены.
