# РЕГЛАМЕНТ РОЗНИЦА ЗАЯВКА

Актуальная редакция: **26.10.2026**.

Этот файл — рабочая GitHub-версия регламента для автоматизации и контроля. При конфликте правил действует **последняя явная инструкция пользователя**.

## 1. Общая задача

По розничной заявке найти товары во всех предоставленных прайсах, выбрать максимально выгодные **подходящие** предложения, корректно сравнить цены, проверить остаток и вложимость, округлить количество вверх до полного транспортного короба и сформировать одну общую машину.

## 2. Источники

1. Сначала проверяются все актуальные прайсы поставщиков.
2. Нельзя останавливаться на первом совпадении.
3. Нельзя придумывать товар, цену, остаток, вложимость, фасовку, производителя или поставщика.
4. Интернет используется только для подтверждения производителя, упаковки и недостающих характеристик. Закупочная цена берётся из прайса.
5. Для выбранной позиции сохраняется трассировка: прайс → лист/строка → товар → цена → единица цены → остаток → вложимость → поставщик.
6. Историческая вкладка `Прод июль-сент 25` — только подсказка. Она не является источником актуальной цены, остатка, вложимости или допуска поставщика.

## 3. Какие строки обрабатывать

- Обрабатывать строки с заполненным количеством.
- `ОТКАЗ` исключать полностью.
- Скрытые пользователем строки считать исключёнными, если не сказано иное.
- Пользовательские комментарии не переписывать от себя.
- По правилам редакции 26.10.2026 пустых рабочих строк быть не должно: если точного товара нет, подбирать максимально близкий допустимый аналог. Пустая строка допустима только по отдельному прямому указанию пользователя.

## 4. Порядок подбора аналога

Проверки выполняются **до сравнения цены**.

1. **Категория — жёсткий первый фильтр.** Бульон → бульон; суп → суп; пюре → пюре; лапша → лапша; готовое рисовое блюдо → готовое блюдо/рис. Нельзя закрывать строку другой категорией ради цены или наличия.
2. **Формат продукта и упаковки.** Мягкая пачка прежде всего заменяется мягкой пачкой, стакан — стаканом, лоток — лотком и т. д.
3. **Масса/объём.** Сначала искать максимально близкую массу. Рабочий ориентир — примерно ±20%, если пользователь не указал иное.
4. **Бренд/линейка.** Тот же бренд или линейка имеют приоритет перед переходом к другому бренду при сопоставимых характеристиках.
5. **Вкус/вариант.** Сначала точный вкус, затем другой вкус той же линейки и формата, затем другая марка той же категории.
6. **Ассортимент.** Нельзя массово использовать один универсальный аналог, если есть другие подходящие варианты.
7. Для корейской лапши и других широких ассортиментных групп обязательно просматривать весь профильный ассортимент до повторения одного аналога.

Ориентир общего смыслового соответствия — около 80%, но он **не отменяет жёсткий фильтр категории**.

## 5. Сравнение цен

- Сравнивать только сопоставимые единицы: ₽/шт с ₽/шт, ₽/кг с ₽/кг, ₽/л с ₽/л.
- При разной фасовке сначала нормализовать цену в общую единицу.
- Исходную цену и единицу поставщика не терять.
- Если цена дана за кг/л, а товар заказывается поштучно, при известной массе/объёме рассчитать цену за штуку.
- Если цена дана за набор, а сравнение идёт за штуку, пересчитать набор на штуку.
- Позиция дороже `Закуп ФАКТ` после корректного пересчёта считается красной и в машину не включается.
- Цена, равная `Закуп ФАКТ`, допустима.
- Скидки применять только там, где они подтверждены для конкретной позиции/группы.

## 6. Остатки, вложимость и округление

- Остаток ограничивает заказ.
- Вложимость брать из прайса/карточки товара, а при отсутствии — подтверждать по надёжному источнику; не выдумывать.
- Многоуровневую вложимость раскрывать полностью: например, `1×5×32 = 160` единиц в транспортном коробе.
- Количество округлять только вверх до полного транспортного короба.
- Вес считать по фактической фасовке выбранного товара и фактическому количеству в машине.

## 7. Поставщики и специальные ограничения

### Полностью запрещены

- `Тэн` — нельзя использовать как основной вариант, аналог, запасной вариант, источник цены или расчёта.
- `Че Ман Су` — полностью исключён.

### Восток / Орими

Общее правило: `Восток` исключён.

Исключение редакции 26.10.2026: товары производителя **Орими** из отдельного прайса Орими разрешены. В рабочем файле:

- поставщик: **Восток**;
- производитель: **Орими**.

Исключение нельзя распространять на другие товары или прайсы Востока.

### Другие специальные правила

- `Махеевъ` — только у `Амбирс`. Если нужной позиции у Амбирса нет, у других поставщиков Махеевъ не искать.
- KDV-продукты/бренды — только из прайса КДВ, когда правило применимо.
- `Владторг` не исключать автоматически.
- Для прайса ВИАНГ поставщик — `ВИАНГ`.
- Richard из прайса Проект Инвест — поставщик `Проект Инвест`.
- Для прайса Черноголовки использовать единое обозначение `Черноголовка (Сах-Трейд)`.

## 8. Производитель и поставщик

Это разные сущности.

- Поставщик определяется строго по прайсу выбранного товара.
- Производитель обязателен; при отсутствии в прайсе его нужно подтверждать надёжным открытым источником.
- Цена должна быть взята из той же строки/позиции, что и выбранное наименование.
- Нельзя переносить поставщика или цену из соседней строки.

## 9. Одинаковые товары и дубли

- Сокращения, перестановка слов, артикулы и служебные обозначения сами по себе не делают товар другим.
- Если это фактически тот же товар, ставить точное совпадение (`ДА`), а не аналог.
- Один и тот же фактический товар у одного поставщика в итоговой заявке объединять: сначала суммировать потребность, затем один раз округлять вверх до полного короба.
- Разные вкусы не объединять в один вкус, если доступны разные варианты.

## 10. Формирование машины

Одна общая машина из всех поставщиков.

Приоритет:
1. позиции, отмеченные магазином как приоритетные;
2. позиции дешевле `Закуп ФАКТ` после нормализации;
3. остальные допустимые, не красные позиции.

Ориентир веса: **18–19 т**, желательно около **18,5 т**. Запас до 20 т оставлять под упаковку и транспортные отклонения.

## 11. Airtable / Excel / Data / GitHub

- Airtable — нормализованная рабочая база: поставщики, товары, прайс-позиции, процессы и связи.
- Excel — компактный пользовательский итог по конкретной задаче.
- Data — независимый аудит после основного подбора: аномальные цены, дубли, неверные единицы, подозрительные аналоги, более дешёвые допустимые варианты. Data не является источником закупочной цены.
- GitHub — регламент, машинные rules, scripts, tests и история изменений.

## 12. Обязательный финальный контроль

Перед выдачей результата заново пройти регламент и проверить:

- запрещённые поставщики отсутствуют;
- Восток используется только для разрешённого Орими-исключения;
- Махеевъ только у Амбирса;
- категория и назначение аналога сохранены;
- нет неоправданно большой разницы массы;
- формат упаковки не ухудшен без необходимости;
- нет чрезмерного повторения одного аналога;
- поставщик совпадает с прайсом;
- производитель подтверждён;
- цена относится к выбранной позиции и приведена к сопоставимой единице;
- остаток достаточен;
- вложимость подтверждена и раскрыта;
- количество округлено вверх;
- вес пересчитан по фактической фасовке;
- историческая вкладка не использована как источник текущей цены/остатка;
- спорные замечания Data перепроверены по сырому прайсу.
